# نظام إدارة مكتب الصيرفة (Sarrafa System)

نظام ويب احترافي لإدارة مكتب صيرفة متخصص ببيع وشراء الدولار مقابل الدينار العراقي.

## 🧱 التقنيات المستخدمة

- **Backend:** Node.js + TypeScript + Express.js
- **Database:** Microsoft SQL Server + Prisma ORM
- **Auth:** JWT + bcrypt (كوكيز HttpOnly)
- **Validation:** Zod
- **Logging:** Winston
- **Frontend:** HTML5 + CSS3 + JavaScript (Vanilla، بدون Framework لتفادي أي خطوة Build إضافية)

> **ملاحظة حول الواجهة الأمامية:** طُلب أصلًا استخدام TypeScript في الواجهة الأمامية، لكن تم بناؤها بـ JavaScript صرف حتى يعمل النظام مباشرة من مجلد `public` دون الحاجة لأداة تجميع (bundler) مثل Webpack/Vite. إذا رغبت بتحويلها إلى TypeScript مع خطوة بناء، يمكن إضافة ذلك كمرحلة منفصلة.

## ⚙️ متطلبات التشغيل

- Node.js 18 أو أحدث

- npm

## 🚀 خطوات التشغيل

### 1) تثبيت الحزم

```bash
cd sarrafa-system
npm install
```

### 2) إعداد قاعدة البيانات

- أنشئ قاعدة بيانات فارغة في SQL Server باسم `SarrafaDB` (أو أي اسم تريده).
- افتح ملف `.env` وعدّل `DATABASE_URL` بمعلومات خادمك الفعلية:

```
DATABASE_URL="sqlserver://localhost:1433;database=SarrafaDB;user=sa;password=YourPassword;trustServerCertificate=true"
```

- عدّل `JWT_SECRET` و `JWT_REFRESH_SECRET` بقيم عشوائية طويلة (لا تتركهما كما هما). يمكنك توليدهما عبر:

```bash
openssl rand -hex 64
```

### 3) تشغيل الترحيل (Migration) لإنشاء الجداول

```bash
npm run prisma:migrate
```

سيُطلب منك اسم للـ migration، اكتب مثلًا `init`.

### 4) زرع البيانات الأولية (مستخدم مدير افتراضي)

```bash
npx ts-node prisma/seed.ts
```

بعد التنفيذ ستحصل على:
- **اسم المستخدم:** `admin`
- **كلمة المرور:** `Admin@12345`

⚠️ **يجب تغيير كلمة المرور فورًا** من داخل النظام بعد أول تسجيل دخول (عبر واجهة API `/api/auth/change-password` — يمكن إضافة زر لهذا في الواجهة لاحقًا).

### 5) تشغيل الخادم في وضع التطوير

```bash
npm run dev
```

الخادم سيعمل على: `http://localhost:5000`
الواجهة الأمامية تُخدَّم تلقائيًا من نفس العنوان (Express static).

### 6) البناء للإنتاج

```bash
npm run build
npm start
```

## 📂 أول خطوة عملية بعد التشغيل

1. سجّل الدخول بحساب `admin`.
2. اذهب إلى **"إعدادات السعر"** وحدد سعر الشراء والبيع الأول (لا يمكن تنفيذ أي عملية بيع/شراء قبل ذلك).
3. لإضافة رصيد أولي للخزينة، نفّذ عملية **"شراء"** يدويًا (مثلاً شراء 1000$ لإدخالها كرصيد ابتدائي) — لاحظ أن هذا يتطلب وجود رصيد دينار كافٍ في الخزينة أولًا؛ يمكن تعديل قيم `Treasury` الابتدائية مباشرة من قاعدة البيانات أو عبر Prisma Studio (`npm run prisma:studio`) إذا رغبت بضخ رصيد ابتدائي دون المرور بعملية شراء فعلية.
4. أنشئ حسابات **موظفين** من صفحة "إدارة المستخدمين".

## 🔐 ملاحظات أمنية مهمة قبل الإنتاج

- غيّر `JWT_SECRET` و`JWT_REFRESH_SECRET` وكلمة مرور `admin` الافتراضية فورًا.
- فعّل HTTPS في الإنتاج (`secure: true` للكوكيز يُفعَّل تلقائيًا عند `NODE_ENV=production`).
- اضبط `CLIENT_URL` في `.env` على النطاق الفعلي للموقع بدل `localhost`.
- راجع صلاحيات مستخدم SQL Server المستخدم في `DATABASE_URL` (يُفضّل عدم استخدام `sa` في الإنتاج، بل مستخدم بصلاحيات محدودة على قاعدة البيانات فقط).
- فعّل نسخ احتياطي دوري لقاعدة البيانات.

## ⚠️ قيود معروفة (Known Limitations)

1. **تصدير PDF بالعربية:** مكتبة `pdfkit` لا تدعم تشكيل الحروف العربية دون خط مُعالَج خصيصًا؛ التقرير الحالي بعناوين إنجليزية. تصدير Excel يدعم العربية بالكامل.
2. **حذف عمليات الشراء القديمة:** لا يُعاد حساب متوسط التكلفة (Weighted Average) بأثر رجعي بدقة كاملة عند حذف عملية شراء قديمة تلتها عمليات أخرى. يُنصح بعدم حذف عمليات الشراء التاريخية، واستخدام آلية "تسوية" (Adjustment) بدلًا من ذلك في نسخة مستقبلية.
3. **رصيد ابتدائي للخزينة:** لا توجد شاشة مخصصة لإدخال رصيد ابتدائي مباشر (Opening Balance) — راجع القسم أعلاه.

## 🗺️ مراحل مستقبلية مقترحة (لم تُنفَّذ بعد)

- اختبارات آلية (Unit / Integration Tests).
- تحسين أداء الاستعلامات على جداول كبيرة (فهارس إضافية، Caching).
- مراجعة أمنية شاملة (Penetration Testing) قبل الإنتاج الفعلي.
- شاشة إدخال رصيد افتتاحي للخزينة.
- دعم تعدد اللغات (عربي/إنجليزي) بالكامل في الواجهة.
- Rate limiting مخصص لكل مستخدم بدل IP فقط.
